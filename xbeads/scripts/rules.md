# Beads Behavioral Rules (xbeads plugin)

## Issue Lifecycle

**Do NOT close issues prematurely.** Wait for explicit user verification that the work is complete. Build succeeding is not enough - the user must confirm the feature works as expected.

**Update status as you work:**
- When starting work: set `status=in_progress`
- When blocked: set `status=blocked`
- When done: wait for user confirmation before closing

## Notes and Design Fields

**Append new information, don't replace.** Use `---` separator for dated updates. Only replace content if explicitly asked.

## Labeling

**Add category labels when creating beads** to help with organization. Common labels: `ui`, `backend`, `daemon`, `docs`, `dx`, `testing`, `infra`.
